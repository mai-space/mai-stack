# M1 — Foundation

> Stand up the networked core: project registry, task lifecycle with typed blockers, and semantic code search over HTTP. Prove the auto-resume loop end-to-end.

---

## Scope

M1 is a **wiring milestone**. Its single proof-of-concept: a child task completing automatically unblocks its parent. Nothing from M2+ (watcher, memory-mcp, dispatcher, dashboard) is built here.

| Service | Type | Port (internal) | Host-exposed |
|---|---|---|---|
| redis | Image | 6379 | No |
| qdrant | Image | 6333 | No |
| mai-registry | New | 3459 | **Yes** |
| mai-project-mcp | Rewrite | 3456 | No |
| mai-code-mcp | Rewrite | 3457 | No |

Both existing tools (mai-space-project-mcp, mai-code-mcp) are **deprecated and rewritten from scratch** as proper Docker services. The old tools may be used as reference material only.

## Build Order

Dependencies flow strictly downward. Each step is a gate.

```
Step 1   Shared files          .env.example, config/*.yml
Step 2   mai-registry          new service; seeds from projects.yml; REST API on :3459
Step 3   mai-project-mcp       rewrite; blocker taxonomy + DAG + auto-resume + Redis events
Step 4   mai-code-mcp          rewrite; HTTP SSE transport; registry sync on startup
Step 5   docker-compose.yml    wire all M1 services on mai network
Step 6   Validation            end-to-end auto-resume scenario
```

### Seed Logic (`seed/fromYaml.ts`)

```
1. Read CONFIG_PATH (env, default /config/projects.yml)
2. If file absent: warn and continue (registry starts empty)
3. For each project in YAML:
   a. Build DB row from config fields
   b. INSERT OR REPLACE using Kysely onConflict().doUpdateSet()
   c. ONLY update config columns — never overwrite last_indexed_at or index_health
4. Log count of upserted projects
```

### Startup Sequence (`src/index.ts`)

```
1. Validate env vars (PORT, DB_PATH)
2. Open SQLite with WAL mode + foreign keys ON
3. migrateToLatest() via Kysely Migrator
4. seedFromYaml(CONFIG_PATH)
5. Register Fastify plugins: cors, routes
6. fastify.listen({ port, host: '0.0.0.0' })
7. SIGTERM → fastify.close()
```

### SQLite Schema

**Migration `001_initial.ts`** — base tables:

```sql
  created_at  TEXT NOT NULL

CREATE TABLE IF NOT EXISTS tasks (
  id             TEXT PRIMARY KEY,

  title          TEXT NOT NULL,
  description    TEXT,
  status         TEXT NOT NULL DEFAULT 'OPEN',  -- OPEN|IN_PROGRESS|DONE|BLOCKED

  created_at     TEXT NOT NULL,
```

**Migration `002_blockers.ts`** — blocker taxonomy and DAG:

```sql
-- SQLite cannot ALTER COLUMN. If status has a CHECK constraint, a table rebuild is required.
-- See RISK 1 below before running this migration.

ALTER TABLE tasks ADD COLUMN parent_task_id TEXT REFERENCES tasks(id) ON DELETE SET NULL;
ALTER TABLE tasks ADD COLUMN blocker_type    TEXT;  -- SUBTASK|DECISION|CLARIFICATION|DEPENDENCY|CAPABILITY|RISK
ALTER TABLE tasks ADD COLUMN blocker_payload TEXT NOT NULL DEFAULT '{}';
ALTER TABLE tasks ADD COLUMN blocker_resolved_at TEXT;
```

### Task State Transitions

```
OPEN          → IN_PROGRESS  (claim_task)
IN_PROGRESS   → DONE         (complete_task)
IN_PROGRESS   → BLOCKED      (any blocker tool)
IN_PROGRESS   → OPEN         (lease expires / reassign_task)
BLOCKED       → OPEN         (blocker resolved; auto-resume for SUBTASK)
DONE                         (terminal)
```

### MCP Tools

All registered in `src/mcp/tools/`. Use `@modelcontextprotocol/sdk` SSE transport at `/sse` + `/message` endpoints on the Fastify server.

**`claim_task`**  
Input: `{ project_id, agent_id, task_types? }`  
Claims the highest-priority OPEN task matching the agent's capabilities. Sets status=IN_PROGRESS, assigned_agent, lease_expires_at (now + TTL). Returns the full task row plus a Context Manifest stub (full assembly in M2).

**`complete_task`**  
Input: `{ task_id }`  
Sets status=DONE. Triggers **auto-resume check** (see below). Publishes state-changed event.

**`renew_lease`**  
Input: `{ task_id, agent_id }`  
Extends lease TTL. Rejected if agent doesn't own the task.

**`create_subtask`**  
Input: `{ parent_task_id, title, description, priority? }`  
1. Validate parent is IN_PROGRESS  
2. INSERT child task with status=OPEN, parent_task_id set  
3. UPDATE parent: status=BLOCKED, blocker_type=SUBTASK, blocker_payload=`{ subtask_id }`  
4. Publish `task.{parentId}.state_changed`  

**`request_decision`**  
Input: `{ task_id, question, options[] }`  
Sets BLOCKED, blocker_type=DECISION, payload=`{ question, options }`. Publishes state-changed + escalation event.

**`request_clarification`**  
Input: `{ task_id, question }`  
Sets BLOCKED, blocker_type=CLARIFICATION, payload=`{ question }`. Publishes events.

**`flag_risk`**  
Input: `{ task_id, description, severity: low|medium|high|critical }`  
Sets BLOCKED, blocker_type=RISK. If severity=`critical`: additionally sets ALL other IN_PROGRESS tasks in the project to BLOCKED. Publishes mandatory review event.

**`reassign_task`**  
Input: `{ task_id, required_capability, reason }`  
Sets status=**OPEN** (not BLOCKED — this re-queues, doesn't pause). Stores blocker_type=CAPABILITY as audit metadata. Clears lease. Publishes state-changed.

### Auto-Resume Logic (`services/blocker.ts`)

This is the core M1 behaviour. Must run **inside the same Kysely transaction** as the `complete_task` update:

```
onTaskDone(completedTaskId):
  1. Fetch completed task's parent_task_id
  2. If null → return
  3. Fetch parent task; check status == BLOCKED and blocker_type == SUBTASK
  4. If not matching → return
  5. COUNT tasks WHERE parent_task_id = parent.id AND status NOT IN ('DONE')
  6. If count > 0 → return  (other subtasks still pending)
  7. UPDATE parent: status=OPEN, blocker_type=NULL, blocker_payload='{}',
                    blocker_resolved_at=now()
  8. [after transaction commit] Publish task.{parentId}.state_changed:
       { from: BLOCKED, to: OPEN, reason: subtask_completed, resolved_by: completedTaskId }
```

Step 5 handles the case where an agent calls `create_subtask` multiple times — the parent only resumes when **all** subtasks are done.

### Redis Events (`redis.ts`)

Published on every state transition. Consumers arrive in M2+, but the events must flow from M1.

```
task.{id}.state_changed   — every status transition
```

Payload: `{ task_id, from, to, blocker_type?, reason?, timestamp }`

If `REDIS_URL` env var is absent, log a warning and continue (graceful degradation for non-Docker use).

### Registry Sync with Retry (`registrySync.ts`)

`depends_on: service_healthy` is not a guarantee of readiness. Retry with backoff:

```typescript
async function syncWithRegistry(registryUrl, qdrant) {
  const delays = [2000, 4000, 8000];
  for (let i = 0; i <= delays.length; i++) {
    try {
      const projects = await fetch(`${registryUrl}/projects`).then(r => r.json());
      for (const p of projects) {
        const collName = `project_${p.id}`;
        const exists = await qdrant.collectionExists(collName);
        if (!exists) {
          await qdrant.createCollection(collName, {
            vectors: { size: vectorDimFor(p.embedding_model), distance: 'Cosine' }
          });
        }
      }
      return;
    } catch (err) {
      if (i === delays.length) { log.warn('Registry sync failed, continuing'); return; }
      await sleep(delays[i]);
    }
  }
}
```

Qdrant collection naming: `project_{id}` (e.g. `project_app-a`).

### Embedding Provider Selection

Parse `EMBEDDING_MODEL` format: `provider:model-name`.

```
ollama:nomic-embed-text    → OllamaEmbeddings (OLLAMA_BASE_URL)
openai:text-embedding-3-small → OpenAIEmbeddings (OPENAI_API_KEY)
cohere:embed-english-v3.0 → CohereEmbeddings (COHERE_API_KEY)
```

Per-project model (from registry) overrides the global `EMBEDDING_MODEL` default.

### MCP Tools

**`search_code`**  
Input: `{ project_id, query, top_k? = 5 }`  
Embeds query → searches `project_{project_id}` Qdrant collection → returns top_k chunks with `file_path`, `line_start`, `content`, `similarity_score`.

**`reindex_project`**  
Input: `{ project_id, incremental? = true }`  
Triggers reindex of the project's workspace path. On completion, calls `PATCH /projects/{id}/index-status` on the registry with `{ last_indexed_at, index_health: 'healthy' }`.

**`list_indexed_projects`**  
Returns all projects from registry with their `index_health` and `last_indexed_at`.

### REST Endpoints

```
GET  /health
POST /reindex/:projectId      202 Accepted; runs async; used by dispatcher (M2)
GET  /reindex/:projectId/status
```

### HTTP SSE Transport

Both `stdio` (when `PORT` is unset) and HTTP SSE (when `PORT` is set) are supported. The same MCP server instance connects to the appropriate transport based on the environment. Per-connection transport instances are required for SSE.

## Dockerfile Pattern (all services)

Every Node.js service uses the same 4-stage Alpine build. `python3 make g++` are required by `better-sqlite3`'s native addon compilation. `curl` is needed for health check commands.

```dockerfile
FROM node:20-alpine AS base
WORKDIR /app
RUN apk add --no-cache python3 make g++ curl

FROM base AS deps
COPY package*.json ./
RUN npm ci --only=production

FROM base AS build
COPY package*.json tsconfig.json ./
RUN npm ci
COPY src/ ./src/
RUN npx tsc --project tsconfig.json

FROM node:20-alpine AS runtime
RUN apk add --no-cache curl
WORKDIR /app
ENV NODE_ENV=production
COPY --from=deps /app/node_modules ./node_modules
COPY --from=build /app/dist ./dist
EXPOSE 3000
CMD ["node", "dist/index.js"]
```

`tsconfig.json` (consistent across all services):
```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true

  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]

```

Use `"module": "NodeNext"` with `.js` extensions on all TypeScript imports.

## Risks

### RISK 1 — SQLite CHECK Constraint on `status` (HIGH)

SQLite cannot `ALTER COLUMN` or modify existing CHECK constraints. If `migration 001` uses `CHECK(status IN ('OPEN','IN_PROGRESS','DONE'))`, adding `BLOCKED` requires a full table rebuild in `migration 002`:

```sql
-- In migration 002, if a CHECK constraint exists:
```

### RISK 2 — MCP SDK SSE Transport API (MEDIUM)

`@modelcontextprotocol/sdk` SSE transport changed between 0.x and 1.x. Pin to `^1.x`. SSE requires creating a new `SSEServerTransport` instance **per connection** — not one shared instance. Check the SDK's current API before implementing.

### RISK 3 — better-sqlite3 Alpine Build (MEDIUM)

The native addon requires `python3 make g++` in the Docker build stage. **Test the Docker build first** before writing service code. If build failures persist, `@libsql/client` (pure JS) is an alternative, though it has trade-off in WAL mode handling.

### RISK 4 — Auto-Resume Transaction Race (LOW in M1, HIGH in M2+)

The "count remaining subtasks" check and the parent status update must be inside a single Kysely `.transaction()`. Two agents completing subtasks simultaneously could otherwise both read count=1 and both trigger the resume. In M1 with single-agent scenarios this is not observable, but the code must be written correctly now.
